## 1. Score markers / score tracker pawn

| Question | Answer |
|---|---|
| Why missing? | Rulebook §2.1 calls for **2 score markers** (one per player). The source has zero standalone images of the markers; the score *track* (digits 0–20) is **already baked into** `game_board_print.png` (top-right strip), but the moveable per-player marker that slides along the track is not provided. |
| Required count | 2 (one per player; tinted to match white / black agent color). |
| Required size | 32×32 px (1×); 64×64 (retina). Sized to occupy roughly 1.5× the height of one digit cell on the baked-in track. |
| Proposed format | **Generated SVG**, then rasterized at build time per `PIPELINE.md` §4 step 4. |
| Proposed authoring spec | Two SVGs: `design/generated/score_marker_white.svg`, `score_marker_black.svg`. Each draws a circular pawn (radius 14, stroked dark, filled with the player's tint), with a thin contrast ring for legibility against the track's gray background. Owner color decisions: white player marker = `#f5f5f5` fill, `#1a1a1a` stroke; black player marker = `#1a1a1a` fill, `#f5f5f5` stroke. |
| BGA placement | Absolute-positioned over the score-track region of `board.png`. Position computed by interpolating between two anchor pixels (digit "0" and digit "20") that A6 will identify in `UI_SPEC.md`. |
| Alternative | Use a CSS-only marker (a `<div>` with `border-radius: 50%` and a colored background). Fully equivalent and avoids one PNG per build. **Recommended** unless the owner wants more elaborate art. |

## 2. Dice faces

| Question | Answer |
|---|---|
| Why missing? | Rulebook §2.1 calls for **6 intel dice**, one per intel color, each with **odd / even** as the trickle-direction signal (rulebook §2.1 + [D-19]: odd = SW trickle, even = SE trickle). The source has zero die-face images. |
| Required count | 6 dice × 2 outcomes = **12 face images**, plus optionally 6 "die at rest, no result" images for the pre-roll state (= 18 total if pre-roll is animated). |
| Required size | 64×64 px (1×); 128×128 (retina). |
| Proposed format | **Generated SVG**, one file per face. |
| Proposed authoring spec | 12 SVGs named `design/generated/die_<intel_id>_<outcome>.svg` where `<intel_id> ∈ {honeypot, industrial_tech, leaked_email, blackmail, security_credential, state_secret}` and `<outcome> ∈ {odd, even}`. Each SVG is a 64×64 rounded-square (corner radius 8) filled with the intel color from [D-19] (`gray`, `brown`, `purple`, `green`, `yellow`, `cyan` respectively), with a centered pip pattern: **odd outcomes** show 1 or 3 or 5 pips, **even outcomes** show 2 or 4 or 6 pips. The simplest legible choice: odd = 1 pip (single dot), even = 2 pips (two dots). The board's "odd \| even" header (already baked into `game_board_print.png`) confirms this binary mapping. |
| BGA placement | A "dice tray" UI region authored by A6 (`docs/specs/UI_SPEC.md`); shown during the `trickle_roll` state and persists into `trickle_resolve` for animation. |
| Alternative | A single 6×2 sprite sheet (`src/img/dice.png`, cell size 64×64, sheet 128×384) generated by the same montage step in `PIPELINE.md` §4. Recommended for performance parity with the other sheets. |

## 3. Action counter UI

| Question | Answer |
|---|---|
| Why missing? | Rulebook §6 (Player Actions) and §3.1 (`actions_remaining`) require a visible "X / 3" or "X / 4" indicator (the "/4" form appears only when the Smuggler boost is active per [D-08]). No source asset exists for this. |
| Required count | 1 UI element (rendered per turn, value derived from server state). |
| Required size | Variable (text-driven). |
| Proposed format | **Pure CSS / HTML**, no PNG/SVG. |
| Proposed authoring spec | A `<div class="action-counter">` containing two `<span>`s: `actions-remaining` and `actions-max` separated by a "/" character. Color/state changes: red text when `remaining == 0`, gold border when `max == 4` (boost active). |
| BGA placement | Top-right of the per-player panel, near the active-player indicator. Visible only during `actions` phase. |
| Alternative | Render as 0–4 small "pip" icons (filled / hollow). Slightly more visual but no source pip art exists; would require a generated SVG. CSS form is simpler and recommended. |

## 4. Turn indicator (active-player highlight)

| Question | Answer |
|---|---|
| Why missing? | Standard BGA pattern — every game shows whose turn it is — but no source asset provides this. The board has a "Turn order" instructional block baked in, which is *static* and does not highlight the active player. |
| Required count | 1 UI element. |
| Required size | Variable. |
| Proposed format | **Pure CSS**, applied to the player panel. |
| Proposed authoring spec | A `.player-panel.is-active` class adds a glowing border (`box-shadow: 0 0 12px <player-color>`) and a small chevron / dot ▶ before the player name. Active state derived from the BGA-standard `active_player` server variable. |
| BGA placement | Around each of the two player panels (top-left of the play area). |
| Alternative | A small generated SVG arrow icon. Not recommended; CSS suffices. |

## 5. Phase indicator (current sub-phase: trickle / spawn / actions)

| Question | Answer |
|---|---|
| Why missing? | Rulebook §5 defines three top-level phases (Trickle, Spawn, Actions), each with sub-states (rulebook §3.1 phase enum: `trickle_draw_left`, `trickle_draw_right`, `trickle_roll`, `trickle_resolve`, `spawn`, `actions`, `end_of_turn_cleanup`, `game_end`). Players must always know which phase is active. The board has a static "Turn order: 1. Trickle… 2. Spawn… 3. Agent actions" sidebar baked in, which lists the phases but does **not** indicate which one is current. |
| Required count | 1 UI element. |
| Required size | Variable; ideally a 3-step breadcrumb or a single label. |
| Proposed format | **Pure CSS / HTML**. The 8 sub-phases collapse to 3 user-visible top-level phases. |
| Proposed authoring spec | A `<ol class="phase-breadcrumb">` with three `<li>`s: "Trickle", "Spawn", "Actions". The `is-current` class adds a colored underline / bold weight. The sub-phase (e.g., "rolling dice…") shows as small italic helper text under the current step. |
| BGA placement | Below the active-player indicator; visible at all times during a turn. |
| Alternative | A floating banner across the top of the play area. UI Mapping Agent (A6) decides; A3 only flags the requirement. |
